    HvacPid.Autotuner (HVAC PID v0.1.1)

    View Source

    Runs a bounded plant experiment and calculates PID settings for review.

    Choose the experiment with :method in start/2. The default :step method changes the output once and observes how the plant settles. The :relay method switches between two output levels and measures the resulting oscillation.

    Once the experiment returns a model, choose the controller form and tuning profile with gains/3. The form selects which PID terms are enabled. The profile selects the formula for their gains. Both choices happen after identification, so you can compare several sets of gains from a single experiment.

    Running an experiment

    The application supplies measurements and elapsed time and writes the returned commands. Keep the controller state for later and route samples to the tuner while the experiment is running. Send each returned command through the usual actuator writer before collecting the next sample. The measured interval should reflect the time the previous command was in effect. For a step test, start near the intended operating point and choose a baseline settling duration that accounts for the plant's response lag.

    On completion or failure, apply the returned exit command and discard the tuner state. Use cancel/1 if an actuator write fails or an override changes the applied command. Use an application watchdog to detect missing samples. The tuner can check limits and timeouts when a sample arrives. The plant can continue moving after an exit command.

    Complete controller and autotuner example

    This example runs entirely in memory. A heating loop starts in automatic mode at 20 °C with a 30% valve command. The simulated room has a 12-second time constant and a three-second delay. The tick function represents applying a valve command, waiting one second, and reading the next measurement. The command history accounts for the delay.

    The controller produces the initial valve command. The tuner takes over for the step test, then returns the valve to its baseline while the result is reviewed. The example accepts a PI setpoint profile, applies its gains, and verifies that the first automatic command matches the output in effect at handoff. The following sample shows the tuned controller beginning to reduce the valve command.

    iex> alias HvacPid.{Autotuner, Controller}
iex> setpoint = 20.0
iex> plant = {20.0, [30.0, 30.0, 30.0]}
iex> tick = fn command, {measurement, [delayed | history]} ->
...>   equilibrium = 20.0 + 0.4 * (delayed - 30.0)
...>   measurement = equilibrium + (measurement - equilibrium) * :math.exp(-1.0 / 12.0)
...>   {measurement, history ++ [command]}
...> end
iex> {:ok, pid} = Controller.new(out_min: 0, out_max: 100, bias: 30)
iex> {:ok, pid} = Controller.set_mode(pid, :automatic)
iex> {measurement, _history} = plant
iex> {:ok, baseline, pid} = Controller.step(pid, setpoint, measurement, 1.0)
iex> opts = [
...>   out_min: 0, out_max: 100, baseline_output: baseline,
...>   step_output: 50, exit_output: baseline,
...>   measurement_min: 15, measurement_max: 35, min_response: 1,
...>   settle_tolerance: 0.05, settle_seconds: 8,
...>   timeout_seconds: 180, max_sample_interval_seconds: 2
...> ]
iex> {:ok, command, tuner} = Autotuner.start(opts, measurement)
iex> result =
...>   Enum.reduce_while(1..180, {tuner, command, plant}, fn _second, {tuner, command, plant} ->
...>     {measurement, _history} = plant = tick.(command, plant)
...>     case Autotuner.step(tuner, measurement, 1.0) do
...>       {:running, next_command, next_tuner} ->
...>         {:cont, {next_tuner, next_command, plant}}
...>       {:ok, exit_command, model} ->
...>         {:halt, {{:ok, model}, exit_command, plant}}
...>       {:error, reason, exit_command} ->
...>         {:halt, {{:error, reason}, exit_command, plant}}
...>     end
...>   end)
iex> {{:ok, model}, exit_command, plant} = result
iex> {measurement, _history} = plant = tick.(exit_command, plant)
iex> {:ok, gains} = Autotuner.gains(model, :pi, :chr_aperiodic_setpoint)
iex> {Float.round(gains[:kp], 2), Float.round(gains[:tn], 2)}
{3.45, 14.19}
iex> {:ok, pid} = Controller.configure(pid, gains)
iex> {:ok, pid} = Controller.set_mode(pid, :automatic)
iex> {:ok, pid} = Controller.track_output(pid, exit_command)
iex> {:ok, command, pid} = Controller.step(pid, setpoint, measurement, 1.0)
iex> command
30.0
iex> {measurement, _history} = tick.(command, plant)
iex> {:ok, command, _pid} = Controller.step(pid, setpoint, measurement, 1.0)
iex> Float.round(command, 2)
28.05

    On a real actuator, apply the exit command on either terminal result and read back the effective output for Controller.track_output/2. Take a fresh measurement when automatic control resumes. Use the same controller direction for the experiment and subsequent control. If the gains are declined or the run fails, the saved controller settings are available for the same handoff when the application requests it.

    Step-response experiment

    Use :step for a self-regulating process that approaches a steady value at each fixed output. For example, a room may settle at one temperature with a valve at 30% and a different temperature with the valve at 40%. The fitted model describes the plant around those operating conditions.

    1. The tuner holds :baseline_output and watches the measurement. A settled window contains at least three samples, spans at least :settle_seconds, and has a maximum-to-minimum spread of at most :settle_tolerance. If the spread grows too large, the window starts again at the latest sample. The average of the settled window is the baseline measurement.
    2. The tuner issues :step_output and starts recording the response. The endpoint window starts when the measurement moves by at least :min_response from the baseline. A sample that returns closer than that discards the endpoint window. The same settling rule applies at the endpoint. The tuner divides the change between the two averaged measurements by the change in output to get the signed process gain, K. A positive gain corresponds to direct action and a negative gain to reverse action. A sign that disagrees with :direction ends the run with :direction_mismatch.
    3. The tuner expresses each measurement as a fraction of the final change. This makes a falling response advance from zero toward one just like a rising response. It linearly interpolates the first crossings of 28.3% and 63.2% at times t₁ and t₂ after the output step. A first-order response reaches those fractions one third of a time constant and one full time constant after the dead time. The estimates are T = 1.5 × (t₂ − t₁) for the time constant and L = t₂ − T for the dead time, both in seconds.
    4. The delay must span at least the wider of the two sample intervals used for interpolation. The tuner waits until at least L + 4T has elapsed after the step and checks every recorded measurement against the fitted response. The maximum allowed error is 10% of the final measurement change. A run can end with :unresolved_dynamics when the crossings or delay cannot be resolved, :poor_fit when the model misses the trace, or :timeout when the plant takes too long to settle or move far enough.

    Relay experiment

    Use :relay when the two configured output levels can repeatedly move the measurement across both sides of a target. With a target of 21 and a :hysteresis half-width of 0.5, the thresholds are 20.5 and 21.5. In direct action, the lower threshold selects :high_output and the upper threshold selects :low_output. In reverse action, the upper threshold selects the high output. Between thresholds the relay holds its current command. At startup it chooses the command that drives the measurement toward the target, using the high output at equality.

    The tuner records peaks and valleys in the timestamped measurements. For reverse action it flips the sign of the measurement relative to the target, so both directions use the same valley-to-valley period calculation. For each cycle, the amplitude is half the difference between the intervening peak and the mean of the two valleys. The first complete cycle is discarded. The tuner then collects ten cycles, requiring at least three samples in each half-cycle. Every amplitude and period in the last five cycles must be within 20% of its respective median. A plant that fails to cross both thresholds eventually times out.

    The median period gives the estimated ultimate period Tu, in seconds. If d is half the difference between the high and low output commands and a is the median measurement amplitude, the estimated ultimate gain is Ku ≈ 4d / (πa). For example, outputs of 30% and 50% give d = 10 percentage points. The estimates characterize the observed oscillation. See Åström and Hägglund's relay method.

    Choosing a gain profile

    The step-response profiles use the fitted K, T, and L to calculate a common gain scale G = T / (abs(K) × L). Each profile sets Kp as a multiple of G and uses either the dead time or time constant for Tn and Td. The controller's direction accounts for the sign of the process gain. Within a given controller form, a larger Kp gives a stronger proportional response. Integral strength scales with Kp / Tn and derivative strength with Kp × Td.

    A setpoint profile targets a change in the requested value, such as raising a temperature setpoint. A disturbance profile targets recovery at a fixed setpoint after a load change, such as opening a door. The Chien–Hrones–Reswick (CHR) aperiodic profiles aim to avoid overshoot. The 20% profiles allow overshoot in their design target and use larger proportional multipliers than their aperiodic counterparts. Actual overshoot depends on the plant and the loop.

    The entries below give (Kp, Tn, Td), with omitted times set to nil. The formulas follow the WAGO CODESYS Modules for Control Engineering Applications note, pages 9–10.

    :chr_aperiodic_disturbanceRecover from a load change at a fixed setpoint with an aperiodic response.(0.3G, nil, nil)(0.6G, 4L, nil)(0.95G, 2.4L, 0.42L)

    For the same step model with K = 0.5, T = 20 s, and L = 5 s, the aperiodic setpoint PI rule gives Kp = 2.8 and Tn = 24 s. The aperiodic disturbance PI rule gives Kp = 4.8 and Tn = 20 s. That second set has both stronger proportional action and stronger integral action for this plant. The two CHR objectives use identical gains within each overshoot category for the P-only form.

    The relay result supports :relay_pid with the :pid form. Its rule uses the oscillation estimates directly, with Kp = 0.25 × Ku, Tn = Tu, and Td = Tu / 8. For example, Ku = 8 and Tu = 24 s give Kp = 2, Tn = 24 s, and Td = 3 s.

    start(opts, initial_measurement)

    @spec start([option()], number()) :: {:ok, float(), t()} | {:error, error()}

    Starts a tuning experiment and returns its initial actuator command.

    Both methods require :out_min, :out_max, and :exit_output in actuator units, :measurement_min and :measurement_max in measurement units, and positive :timeout_seconds and :max_sample_interval_seconds. Measurements must be strictly inside their limits. Commands can use either output bound.

    The default method: :step also requires distinct :baseline_output and :step_output, positive :settle_seconds, and positive :settle_tolerance and :min_response in measurement units. The tolerance must be smaller than the minimum response.

    For method: :relay, supply :low_output below :high_output, a measurement :target, and a positive :hysteresis half-width. Both switching thresholds must lie strictly inside the measurement limits.

    The default direction is :direct. The default sample budget is 10_000 and includes the initial measurement.

    step(tuner, measurement, elapsed_seconds)

    @spec step(t(), number(), number()) :: progress()

    Processes a measurement and the positive elapsed time since the previous sample.

    Apply the command in each :running result and retain its tuner state. Terminal results include the configured exit command. A measurement on either limit aborts the experiment. Timeout is measured from start/2.
